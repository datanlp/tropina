# Журнал разработки Tropina

## 2026-11-15 — этап 1: каркас

**Что сделали**

- Репозиторий `datanlp/tropina`, ветка `stage-1-skeleton`. Next.js 16.4.6 (App Router, Cache Components включены по умолчанию в `create-next-app`), TypeScript strict.
- Языки: en (по умолчанию), pl, ru и **uk** — украинский добавлен по решению владельца после стартового промпта.
- Адреса `/{lang}/poland/christmas-markets[/{city}[/{market}]]`, редирект `/` по языку браузера, `/{lang}` → страница ярмарок.
- Схема данных на zod, 2 TEST-записи (Краков, Вроцлав), проверка данных перед каждой сборкой.
- Тесты написаны раньше кода: 36 unit (Vitest), 48 e2e (Playwright, desktop + Pixel 7), axe (WCAG 2.2 AA) в каждом e2e-тесте через auto-фикстуру.
- ESLint 9 + jsx-a11y (strict, 33 правила), Prettier, CI в GitHub Actions (format, lint, typecheck, unit, build, e2e).
- Время от «ок» на план до зелёного прогона: ~15 минут.

**Что сломалось и как починили**

- `npm install` с Vitest 5.1 упал на peer-зависимости: Vitest 5 требует `@types/node` ≥ 22, шаблон Next ставит 20. Подняли до 22. ~2 минуты.
- `eslint-plugin-jsx-a11y` 6.10 официально поддерживает ESLint только до 9. Остались на ESLint 9 (его же ставит `create-next-app`).
- В Next 16 `middleware.ts` переименован в `proxy.ts` — сверили по документации в `node_modules/next/dist/docs`, а не по памяти.
- С Cache Components `generateStaticParams` не может вернуть пустой список — иначе сборка падает. В продакшене ярмарок пока нет (TEST-записи исключены), поэтому для пустого списка отдаётся заглушка `__none__`, которая отвечает 404. Исчезнет сама, когда появятся настоящие данные.
- Тест «неизвестная ярмарка → 404» мигал: первый запрос отдавал 200. Причина — Partial Prerendering: оболочка страницы уже ушла клиенту с кодом 200, а `notFound()` сработал позже (soft 404). Починили проверкой в `proxy.ts`: неизвестные город/ярмарка переписываются на 404 до рендера. ~5 минут.
- Переменную `TROPINA_INCLUDE_TEST_DATA` вшиваем при сборке через `env` в `next.config.ts`, чтобы страницы и proxy всегда видели один и тот же набор данных.

**Решения и почему**

- next-intl берёт язык из `next/root-params`, а не из заголовков: страницы остаются статическими.
- `localeCookie: false` в next-intl: по умолчанию он ставит cookie `NEXT_LOCALE`, а у нас «без cookies». E2E-тест проверяет, что cookies нет.
- Названия языков в переключателе тоже лежат в `messages/*.json` — ни одной строки интерфейса в коде.
- Скрипты через `cross-env`, чтобы `npm run dev` работал и на Windows.

## 2026-11-15 — этап 2: карта и список

**Что сделали**

- MapLibre GL 6.18 + OpenFreeMap (стиль `liberty`), без ключей. Точки ярмарок из GeoJSON, группировка в кружки с числом до 9-го зума, выбранная точка крупнее и с тёмной обводкой (не только цвет).
- Список рядом с картой: кнопка «Показать на карте» (`aria-pressed`) подсвечивает точку и открывает подсказку со ссылкой на карточку; клик по точке выделяет строку списка и прокручивает к ней. На телефоне переключатель «Карта / Список».
- Подписи элементов карты (кнопки зума и т.п.) переведены на 4 языка через `locale` MapLibre.
- Карточка ярмарки: «Как добраться» (Google Maps по координатам), «Официальный сайт», транспорт, доступность, адрес.
- Если карта не загрузилась (нет WebGL или сети), показывается пометка, список работает полностью.
- В CI добавлен job со скриншотами на данных LOREM с настоящими тайлами (артефакт `screenshots`).
- Тесты: 42 unit, 59 e2e (+11 к этапу 1), axe в каждом.

**Что сломалось и как починили**

- MapLibre 6 запускает web worker отдельным файлом рядом со своим модулем; бандлер этот URL не видит. Копируем `maplibre-gl-worker.mjs` в `public/vendor/` перед `dev`/`build` и задаём `setWorkerUrl`. ~5 минут.
- axe нашёл реальную проблему: ссылка «Перейти к содержимому» при фокусе перекрывала логотип (target-size). Теперь при фокусе она встаёт отдельной строкой над шапкой.
- Две ошибки в только что написанных тестах (ещё до первого зелёного прогона): кнопка «Map» совпадала по подстроке с «Show on map» (нужен `exact: true`), а на телефоне скрытую карту роль-селектор не видит без `includeHidden`. Исправили селекторы, проверки остались те же.
- В облачной среде разработки тайлы OpenFreeMap недоступны (сеть закрыта), поэтому живую карту проверяем скриншотами из GitHub Actions.

**Решения и почему**

- Слои кружков на WebGL, а не HTML-маркеры: быстрее при большом числе точек. Клавиатурный и скринридерный доступ ко всем ярмаркам даёт список (так в требованиях).
- При выборе из списка на телефоне вид не переключается сам на карту: меньше неожиданных прыжков, карта в один тап.

## 2026-11-15 — этап 3: фильтры и логика дат

**Что сделали**

- `src/lib/schedule.ts`: «открыто сейчас», «в эти выходные», «сезон закончился» по времени Europe/Warsaw (через `Intl.DateTimeFormat`, без библиотек дат). Часы через полночь (18:00–01:00), переход на летнее время, исключения 24–26 декабря.
- В схему добавлено необязательное поле `hoursExceptions` (дата + `closed: true` или свои часы). Текстовая пометка `hoursNote` осталась для людей, новое поле нужно для логики.
- Фильтры «Открыто сейчас / В эти выходные / Все» (радиокнопки в `fieldset`) управляют и списком, и картой. Прошедшие ярмарки скрыты. На странице ярмарки статус: «Открыто сейчас», «Сейчас закрыто», «Сезон ещё не начался», «Сезон закончился, ждём в следующем году».
- Время берётся только в браузере (`useSyncExternalStore`, обновление раз в минуту): страницы остаются статическими, фильтр применяется сразу после загрузки.
- Тесты: 62 unit (+20), 73 e2e (+7). Время в e2e фиксируется через `page.clock`.

**Что сломалось и как починили**

- Ничего серьёзного. Одна ошибка типов в TypeScript на объединении «закрыто / часы» — заменили проверку на `"closed" in exception`. ~1 минута.
- Нашли скрытую мину: e2e-тесты этапа 2 зависели от реальной даты и в январе 2027 упали бы (TEST-сезоны кончаются в декабре). Теперь общая фикстура ставит часы браузера на 1 декабря 2026, тест может поставить своё время.

**Решения и почему**

- Фильтр считается на клиенте, а не на сервере: иначе страницы стали бы динамическими (время запроса), а статика быстрее и дешевле на хостинге.
- «В эти выходные»: с понедельника по субботу — ближайшие суббота и воскресенье, в воскресенье — только сегодня.

## 2026-11-15 — этап 4: страницы городов и SEO

**Что сделали**

- Meta на всех страницах: title, description, canonical и hreflang для en/pl/ru/uk + `x-default` (через `alternates` в `generateMetadata`). У страницы ярмарки ещё Open Graph.
- `sitemap.xml` (главная, города с несколькими ярмарками, все ярмарки, каждая на 4 языках с перекрёстными hreflang) и `robots.txt`.
- JSON-LD `Event` на странице ярмарки (даты, место, координаты, язык), с защитой от `</script>` в тексте.
- Город с одной ярмаркой → редирект 307 на её страницу прямо в `proxy.ts` (до рендера, как и 404).
- Тесты: 69 unit (+7), 85 e2e (+12).

**Что сломалось и как починили**

- Ничего не сломалось. Один тест этапа 1 («страница города показывает список») противоречит требованию этапа 4 о редиректе: обе TEST-ярмарки в разных городах. Тест переписан под новое поведение («адрес города открывает его единственную ярмарку»), это изменение требования, а не подгонка.

**Решения и почему**

- Редирект временный (307), а не постоянный: когда в городе появится вторая ярмарка, страница города вернётся, а постоянный редирект браузеры и поисковики запомнили бы.
- hreflang только из метаданных страницы, заголовок `Link` от next-intl выключен (`alternateLinks: false`), чтобы не было двух источников.
- Города с одной ярмаркой не попадают в sitemap: это только редирект.

## 2026-11-15 — этап 5: PWA и аналитика

**Что сделали**

- `app/manifest.ts` (Tropina, standalone, цвет #a3122a), временные иконки 192/512/maskable и apple-touch-icon (красный квадрат с «T»; заменить на настоящий логотип).
- Свой service worker `public/sw.js`: при установке сохраняет страницу списка и все карточки на 4 языках (список берёт из `/offline-pages.json`) вместе с их JS/CSS; страницы — сначала сеть, потом кэш; `/_next/static` — сначала кэш; тайлы OpenFreeMap — из кэша с фоновым обновлением, не больше 600 штук. Кэши версионируются по `TROPINA_BUILD_ID`, старые удаляются при активации.
- Подсказка установки после второй открытой карточки: на Android — системное окно (`beforeinstallprompt`), на iPhone/iPad — текст «Поделиться → На экран „Домой“». Кнопка «Не сейчас» скрывает её навсегда (localStorage), в установленном приложении не показывается.
- `track(event, props)` в `src/lib/analytics.ts`, провайдер Umami меняется в одном месте. События: market_open, official_link_click, directions_click, filter_change, install_prompt_shown, app_installed, lang_change. Скрипт Umami Cloud подключается, только если задан `NEXT_PUBLIC_UMAMI_WEBSITE_ID`; без него аналитика молчит.
- Тесты: 76 unit (+7), 95 e2e (+10).

**Что сломалось и как починили**

- Serwist 9.5 (`@serwist/turbopack`) экспортирует `dynamicParams` из route handler, а с Cache Components это запрещено — сборка падает. Вместо библиотеки написали SW вручную (~100 строк). Около 10 минут.
- Подсказка на iPhone не появлялась: тест открывает вторую карточку раньше, чем первая успевает стать интерактивной, и визит не засчитывался. Теперь визит записывается маленьким inline-скриптом прямо при разборе HTML. Около 5 минут.

**Решения и почему**

- Umami Cloud Hobby: бесплатно до 100 тыс. событий в месяц, без cookies, без своего сервера. Если вырастем — меняется только провайдер в `analytics.ts` и тег скрипта.
- Страницы городов в офлайн-кэш не кладём: город с одной ярмаркой отвечает редиректом, а SW не может отдавать редирект на навигацию.

## 2026-11-15 — этап 6 (часть 1): Lighthouse и подготовка к настоящим данным

**Что сделали**

- Lighthouse, телефонный профиль, сборка с TEST-данными: список ярмарок — производительность 85 → 99 (TBT 610 → 100 мс, TTI 4,8 → 2,3 с), доступность 100; карточка — 99–100 по всем четырём категориям. Десктоп (pl): 100 / 100.
- MapLibre (самый тяжёлый скрипт) теперь грузится, только когда блок карты виден на экране, и только в простое браузера. На телефоне сначала показывается список, поэтому карта не мешает ему стать интерактивным.
- `npm run lighthouse` (`scripts/lighthouse.mjs`): проверяет страницы на запущенном сайте и падает, если производительность или доступность ниже 90. В CI запускается в job превью (LOREM-данные, настоящие тайлы) на 4 страницах в en/ru/uk; HTML-отчёты лежат в артефакте вместе со скриншотами.
- `docs/market-card-template.md` — шаблон карточки для настоящих данных; `docs/phone-check.md` — 12 пунктов проверки на iPhone и Android.

**Что сломалось и как починили**

- Ничего. В контейнере тайлы OpenFreeMap недоступны, поэтому «best practices» там 96 из-за ошибки в консоли; в CI с настоящими тайлами этого нет.

**Решения и почему**

- Порог 90 только для производительности и доступности, как в брифе. SEO и best practices выводятся, но сборку не роняют.
- Проверка на телефонах и загрузка настоящих карточек ждут владельца: нужен адрес сайта (превью на Vercel) и сами карточки.

## 2026-11-16 — дизайн: карта как главный экран

**Что сделали**

- Три итерации дизайна. Первая («зимняя ярмарка», кремовый фон) оказалась владельцу слишком скромной. Потом два смелых варианта с SVG-иллюстрацией (ночной город и «пряничный Гданьск»). В итоге владелец прислала свой макет приложения, где карта — главный экран; сделали по нему.
- Стиль карты: слой OpenFreeMap «liberty» перекрашивается при загрузке в тёплые тона (`warmUp` в `MarketMap.tsx`). Слои сопоставляются по типу и имени, поэтому переименованный слой просто остаётся в исходном цвете.
- Метки: HTML-маркеры (бордовая «капля» с ларьком) для одиночных точек, круги для кластеров. Подпись «название · до 26.12» видна с зума 11 и у выбранной метки. Метки кнопки с `tabindex=-1`: для клавиатуры путь через список.
- Нижняя карточка (`MarketSheet.tsx`): фото или наша SVG-иллюстрация, название, «Рождественская ярмарка», даты, адрес, «Подробнее», «Прислать своё фото». Заменила попап MapLibre.
- Данные: необязательное поле `photo` (`src` только с нашего сайта, `alt` на 4 языках, `source: ai | official | user`, у `user` обязателен `credit`). У фото с `source: "ai"` на самой картинке всегда видна плашка «Сгенерировано ИИ». Тесты: `tests/unit/photo.test.ts`.
- Ссылка «Прислать своё фото» берётся из `NEXT_PUBLIC_PHOTO_FORM_URL`; без переменной кнопка скрыта. В `npm run dev` стоит заглушка на example.com.
- Телефон: по умолчанию карта сверху и список под ней; плавающий переключатель «Карта / Список» внизу. В режиме «Карта» она на весь экран, заголовок остаётся только для скринридера. Языки в шапке кодами EN/PL/RU/UK, полное название в имени ссылки.
- Шрифты Playfair Display (заголовки) и Inter через `next/font/google` с кириллицей; файлы раздаются с нашего домена.

**Что сломалось и как починили**

- Блок карты высотой 0 из-за CSS MapLibre (`.maplibregl-map { position: relative }`). Здесь закрыто правилом `.explorer .explorer__canvas`; в соседней ветке `fix/map-canvas-height` своя починка, при мёрже оставить одну.
- Около 10 минут не работала запись файлов (сбой проверки автодопуска), продолжили по таймеру.
- Тайлы OpenFreeMap в облачном контейнере закрыты, поэтому скриншоты сняты с подменённым однотонным стилем: улиц на них нет.

**Решения и почему**

- Третье состояние вида `both` (карта и список вместе) вместо «только список» по умолчанию на телефоне. Так экран начинается с карты, а существующие тесты (список видим по умолчанию, переключатель прячет одно из двух) проходят без изменений.
- Поиск, категории (еда, покупки), нижняя панель вкладок и 3D-иллюстрации достопримечательностей из макета отложены по решению владельца.
- Карта на телефоне теперь видна сразу, значит MapLibre грузится раньше. Lighthouse-проверка в CI покажет, держится ли производительность ≥ 90.
